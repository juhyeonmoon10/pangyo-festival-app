# 판교고 축제 모바일 웹앱

판교고 연말 축제를 위한 모바일 우선 부스 탐색 UI입니다. 현재 저장소는 ORBIT P0 가이드를 참고해 개인 저장소에서 개발하는 독립 프로토타입입니다.

공개 미리보기: <https://pangyo-festival-app.vercel.app/>

## 현재 구현

- 홈, 부스, NFC, 축제 패스, 내 정보의 5개 학생 화면
- 1~4층 학교 지도와 드래그 가능한 Bottom Sheet
- 부스 검색, 층 선택, 상세 화면
- 부스 운영 상태: `preparing`, `open`, `paused`, `closed`
- 내 정보에서 앱 표시 이름 변경: 기존 Supabase Auth 메타데이터 사용, Google 계정 이름·학번·방문 기록 유지
- 첫 로그인 이름은 Google 프로필에서 자동으로 가져오고 학번만 입력한다. Google 이름이 없거나 기존 길이 제한을 넘을 때만 이름 입력을 요청한다.
- 행사 공지와 비상 모드 UI
- NFC 성공, 중복, 운영 중지, 미등록 태그 결과 UI
- NFC 실패 시 운영자 수동 승인 안내
- 320px 모바일, iOS safe area, 모션 감소 설정 대응
- 관리자 화면에 실제 부스 운영, NFC, 방문·참여자, 포인트, 바우처 발급·사용·감사 기록 연결

## 중요한 제한

2026-09-30 기준 Google/Supabase 인증과 NFC 발급에 더해 운영 현황, 참여자 조회, 부스 추가·상태·프로그램 안내, 수동 방문 승인, 리뷰 포인트, 바우처 발급·QR·사용·취소를 서버 RPC로 연결했습니다. `?demo=1`은 여전히 격리된 체험 모드입니다.

기능 연결과 행사 출시 승인은 다릅니다. 실제 학생 대상 개장 전에는 실제 Google 계정 2개와 휴대전화로 리허설하고 다음 미완료 항목을 확인해야 합니다.

- 학교 승인 계정 제한과 개인정보 보존·삭제 정책
- 현재 `users.admin`에 의존하는 전역 관리자 대신 행사별 담당 부스 권한
- 실제 NFC 카드, 카메라, Google 로그인 검증
- 실제 동시 접속 부하·백업 복구 검증

자세한 차이는 [P0_GAP_AUDIT.md](./P0_GAP_AUDIT.md)에 기록합니다.

실제 서버 연결 전 DB·권한·NFC·API 계약은 [SERVER_DB_API_DESIGN.md](./SERVER_DB_API_DESIGN.md)에 정리합니다.

## 서버 운영 기능 사용

1. 관리자 계정으로 로그인하고 **내 정보 → 운영자 도구**로 이동합니다.
2. **운영 현황**에서 행사 이름, 상태, 글 후기 포인트를 저장합니다. 설치 자체는 행사를 생성하거나 개장하지 않습니다.
3. **부스 관리**에서 위치·안내·운영 상태를 확인합니다. 처음 가져온 기존 부스는 모두 일시 중지입니다. 신규 부스는 수동 방문 승인을 지원하며 기존 enum 기반 NFC 발급 대상으로 자동 추가되지 않습니다.
4. **바우처 설정**에서 이름, 필요한 완성 스탬프 수, 총 발급 한도, 한국 시간 기준 마감, 자동 발급 여부를 정합니다. 조건을 달성한 참여자는 자동 발급되거나 내 바우처에서 받을 수 있습니다.
5. **참여자**에서 번호를 확인한 뒤 **방문 기록 / 포인트 / 발급·사용**에서 처리합니다. 수동 변경에는 사유가 필요하며 본인 보상 조정은 거부됩니다.
6. 바우처 QR은 90초 동안 유효합니다. 운영자는 QR을 읽거나 인증 코드를 입력하고 참여자·상품을 확인한 다음 사용 완료 처리합니다. 카메라 미지원 브라우저에서는 인증 코드 입력을 사용합니다.

새로운 서버 기록은 `festival_ops`의 9개 테이블에 격리됩니다. 브라우저의 직접 테이블 접근은 막고 `festival_ops_read`, `festival_ops_write`만 허용합니다. 기존 `users.money`, 기존 테이블 정의·RLS 정책·NFC 함수는 변경하지 않습니다. 새로운 RPC는 기존 NFC 검증 함수를 호출하되 운영 상태를 확인한 뒤 행사별 방문을 같은 트랜잭션에 기록합니다.

기존 `completed_booths`·리뷰 기록은 삭제하거나 날짜를 만들어 이관하지 않습니다. 운영 기능을 설정하면 현재 행사 기록만 스탬프·보상 계산에 사용합니다. 이전 기록의 이관은 별도 검토가 필요합니다. 기존 NFC RPC를 직접 호출하는 이전 버전 앱은 새 운영 기록을 만들지 않습니다.

공용 프로젝트에 승인 후 적용한 스키마는 [operations-server/install.sql](./operations-server/install.sql)입니다. 재실행하지 마십시오. 비상 중지는 [operations-server/disable.sql](./operations-server/disable.sql)로 새 RPC 접근만 막으며 기록을 삭제하지 않습니다. 새 테이블이 기존 사용자 ID를 참조하므로 사용자 삭제 전 관련 기록 보존·처리 절차가 필요합니다.

포인트는 기존 가상화폐와 별개이며 글 후기 최초 등록 시에만 지급됩니다. 재요청 고유키, 중복 제약, 서버 트랜잭션으로 이중 지급·이중 사용을 방지합니다. 쓰기는 현재 하나의 운영용 advisory lock으로 직렬화합니다. 정확성을 우선한 초기 구현이므로 행사 예상 부하 검증 없이 처리량을 가정하지 마십시오.

### 운영 기능 검증

- `tests/operations-isolated.mjs`: PGlite와 합성 인증/Vault 환경의 권한·중복·포인트·발급·사용·취소·중지 검증
- `tests/operations-client.cjs`: 요청 중복 합치기, 응답 유실 후 재시도, 계정 변경, 민감 정보 없는 재시도 키 저장
- `tests/operations-browser.mjs`: Chromium → 격리 SQL 연결, 320/390/430px 흐름과 스크린샷. 실제 Supabase 요청은 모두 가로챕니다.
- 실제 Google OAuth, 다중 PostgreSQL 연결 경합, 실제 카메라·NFC는 자동 테스트가 증명하지 않습니다.
- 2026-09-30 검증: 격리 SQL 20/20, 계정·NFC 결과 UI·요청 클라이언트 단위 테스트 36/36, 320/390/430px 브라우저 흐름 통과. 공용 서버에서는 새 테이블 9개 RLS, 익명 RPC 차단, 기존 public 컬럼·정책·NFC 함수 해시 보존을 확인했습니다. 실제 학생 기록은 점검용으로 조회하지 않았습니다.

## 로컬 실행

정적 웹앱이므로 `index.html`을 브라우저로 열 수 있습니다.

```text
outputs/pangyo-festival-app/index.html
```

NFC URL 테스트 예시:

```text
index.html?nfc=NFC-G1-01
```

## 자동 테스트

`tests/map-performance-smoke.cjs`는 다음 흐름을 확인합니다.

- 320px 가로 넘침
- 하단 메뉴 5개와 화면 전환
- 지도 반복 렌더링 성능
- NFC 샘플 적립과 중복 처리
- 축제 패스 반영

테스트에는 Playwright와 Chrome 경로가 필요합니다.

## 저장소 경계

- 이 저장소는 개인 개발 저장소입니다.
- `elilim09/ORBIT` 공용 저장소와 공용 Supabase를 자동으로 수정하지 않습니다.
- ORBIT 반영은 팀 검토와 명시적 승인 후 별도 작업으로 진행합니다.

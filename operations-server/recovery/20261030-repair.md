## Recovery

1. If installation fails before commit, the transaction rolls back all four replacements.
2. If a post-install regression appears, apply `20261030-stop-affected-actions.sql`
   with project-owner approval to stop reset and the legacy self-confirm endpoint.
   Identity status is temporarily unavailable, but stored records are unchanged.
3. Do not restore the old definitions automatically: they re-enable impersonation
   and deletion of shared quest data. The JSON snapshot is diagnostic evidence only.
4. Reproduce and fix in isolation, reapply the corrected repair SQL, then verify metadata
   and an approved test account. Reapplying restores only the existing RPC execute grants.

No production reset is needed to verify deployment. Read function hashes, permissions
and migration history instead. Do not use real student transactions as smoke tests.
